# DocShift 技术选型

## 1. 文档目的

本文档集中维护项目使用的语言、框架、运行时、外部工具和基础设施选型。模块职责、数据关系和交互流程见《架构设计.md》。

选型状态：

- **已确认**：用户已经确认，可作为开发基线。
- **推荐待确认**：架构建议采用，但开始编码前仍需确认。
- **待确定**：需求尚未明确，不在本文擅自锁定。

## 2. 已确认选型

| 层级 | 选型 | 状态 | 说明 |
| --- | --- | --- | --- |
| 前端框架 | React 19.2.7 | 已确认 | 前端业务界面使用的 React 版本。 |
| 后端语言标准 | C++17 | 已确认 | C++ API 服务的语言标准。 |
| 后端 Web 框架 | Drogon | 已确认 | 用于 HTTP API、路由和异步网络处理；具体版本待锁定。 |
| 后端构建系统 | CMake | 已确认 | 使用 target-based CMake 管理服务端目标；具体最低版本为 3.16。 |
| 容器化 | Docker | 已确认 | 前端、API、Worker 等以镜像交付。 |
| 文件持久化 | 后端机器指定目录 | 已确认 | 通过 `DOCSHIFT_STORAGE_ROOT` 配置，并挂载给 API 与 Worker。 |
| 用户与邮件 | 网易邮箱 SMTP | 已确认 | 用于发送首次注册的邮箱验证码。 |
| 缓存/消息组件 | 不使用 Redis | 已确认 | MVP 不部署 Redis。 |

React 官方当前将 19.2 列为最新版本，并列出 19.2.7 为该系列最新补丁版本；项目依赖应固定到 `19.2.7`，而不是使用无边界的版本范围。[React Versions](https://react.dev/versions)

## 3. 推荐待确认选型

| 场景 | 推荐选型 | 原因 |
| --- | --- | --- |
| 业务元数据与事务 | PostgreSQL | 适合保存用户、Task、转换项、验证码状态、审计记录和任务领取状态。 |
| 异步转换调度 | PostgreSQL 任务表 | 单机 MVP 可在同一事务中创建转换项和待执行任务，避免引入 Redis。 |
| 前端静态资源与反向代理 | Nginx | 托管 React 构建产物，并将 `/api/*` 转发至 C++ API。 |
| 文档转 Markdown | MarkItDown | 适用于 DOCX、PPTX、XLSX、HTML、PDF 等输入转 Markdown。 |
| Markdown 转 DOCX / HTML | Pandoc | 适用于 Markdown 到 DOCX、HTML 的生成。 |
| Markdown 转 XLSX | 独立 Python 转换模块 | 解析 Markdown 表格并生成 XLSX；不将该职责交给 Pandoc。 |
| XLSX 生成库 | openpyxl | Python 转换模块的候选库，用于生成工作簿和预览描述。 |

## 4. 明确不采用

| 选项 | 当前结论 | 原因 |
| --- | --- | --- |
| Redis | MVP 不采用 | PostgreSQL 任务表能满足当前单机异步转换；额外引入 Redis 会增加容器和状态维护成本。 |
| MinIO / S3 | MVP 不采用 | 文件先保存到后端机器指定目录，不增加对象存储服务。 |
| PDF 转 DOCX | 不提供 | 不承诺 PDF 到 Word 的结构与排版可靠性。 |
| 临时访客用户 | 不提供 | 系统仅面向注册用户，Task 和文件均绑定真实 `user_id`。 |

Redis 仅在未来出现跨机器高吞吐任务调度、大规模实时消息扇出、分布式限流或明确的热点缓存需求时再评估。

## 5. 版本与运行时锁定规则

- React 已锁定为 `19.2.7`。
- C++ 代码以 C++17 编译。
- Pandoc、MarkItDown、Python、openpyxl、PostgreSQL、Nginx、操作系统基础镜像的具体版本必须在编码前确认并固定。
- Docker 镜像使用明确版本标签，不使用浮动的 `latest` 标签。
- 依赖升级应先在测试环境完成格式转换回归后再进入生产环境，尤其是 Pandoc 和 MarkItDown。

## 6. 待确定的技术项

1. Drogon 具体版本和 C++ 单元测试框架。
2. PostgreSQL、Python、Pandoc、MarkItDown、openpyxl、Nginx 和基础镜像的具体版本。
3. C++ API 与 Python Worker 的进程启动方式和镜像基础发行版。
4. 网易 SMTP 的主机、端口、TLS 方式，以及授权码的机密配置注入方式。
5. 生产部署目标：本机 Docker、内网私有化或公网服务。

上述项目确认后，再写入具体依赖清单、Dockerfile 和部署配置。
