# DocShift 功能文档（MVP）

## 1. 文档目的

本文档整理 DocShift 第一阶段需要实现的文档转换功能，作为后续方案设计、开发和测试的依据。

本文只描述功能需求；语言、框架、转换工具、运行时版本和容器化选型见《技术选型.md》。

已确认的功能边界：不提供 PDF 转 DOCX 功能。

## 2. MVP 范围

首期目标是提供“创建转换 Task、在 Task 中配置多份不同文档的转换、服务端暂存与预览、删除不需要的结果、确认后按 Task 导出”的完整闭环。

### 2.1 Task 模型

- 用户在 Web 页面中创建一个 Task，Task 是一次文档转换工作的容器。
- 一个 Task 可以包含多份源文件；各文件的源格式、目标格式和转换路径可以不同。
- Task 内每一份源文件及其转换配置形成一个独立的“转换项”。转换项独立上传、排队、转换、预览、删除和导出。
- 转换项成功后生成的结果文件归属于该 Task；用户可在同一 Task 中集中预览、删除和导出保留的结果。
- Task 内某个转换项失败、删除或过期，不影响其他转换项的转换结果。

### 2.2 用户体系

- 系统提供用户账户；用户的基本资料保存在数据库中，Task、源文件、结果文件和预览文件均归属于真实 `user_id`。
- 用户名和邮箱均为用户基础信息，且应保持唯一。
- 用户首次注册时，必须输入邮箱验证码；验证码通过网易邮箱 SMTP 服务发送和校验后，账户才可创建或激活。
- 用户头像文件保存于后端机器指定的用户目录；数据库保存头像文件资产标识或相对路径，不保存后端机器的绝对路径。
- 用户可查看和更新自己的基本资料与头像；头像的格式、大小上限及是否保留历史头像待确认。
- 注册成功后的登录方式（密码登录、每次邮箱验证码登录或其他方式）尚未确认，不在本文中擅自定义。

### 2.3 支持的转换矩阵

| 源文件格式 | 目标格式 | 功能状态 | 说明 |
| --- | --- | --- | --- |
| DOCX | Markdown | 必须实现 | 提取文档正文结构并生成 Markdown。 |
| PPTX | Markdown | 必须实现 | 提取幻灯片中的文本内容并生成 Markdown。 |
| XLSX | Markdown | 必须实现 | 提取工作表和表格内容并生成 Markdown。 |
| HTML / HTM | Markdown | 必须实现 | 提取页面正文结构并生成 Markdown。 |
| PDF | Markdown | 必须实现 | 提取可解析的文本内容并生成 Markdown；不承诺 OCR 能力。 |
| Markdown / MD | DOCX | 必须实现 | 将 Markdown 生成 Word 文档。 |
| Markdown / MD | HTML | 必须实现 | 将 Markdown 生成 HTML 文件。 |
| Markdown / MD | XLSX | 必须实现 | 将 Markdown 中的表格导出为 Excel 工作簿。 |
| PDF | DOCX | 明确不实现 | 不在首期及当前规划范围内。 |

说明：首期不承诺“任意格式互转”。每个转换路径应独立校验并给出明确的成功或失败结果。

## 3. 前端功能

### 3.1 用户注册与资料

- 提供用户名、邮箱和邮箱验证码的注册页面。
- 用户填写邮箱后可请求验证码；页面应展示发送中、已发送、验证失败及发送受限等状态。
- 用户完成首次邮箱验证后才能创建或激活账户。
- 已登录用户可查看并修改自己的基础资料，并上传或替换头像。
- 头像上传失败时必须展示明确原因，且不得覆盖当前可用头像。

### 3.2 文档上传

- 已登录用户先创建一个 Task，再向该 Task 的待转换区添加文件。
- 用户可一次选择多个待转换的本地文件上传。
- 页面提供待转换区，用户可将一个或多个文件拖拽至该区域加入上传队列。
- 用户也可通过文件选择控件添加文件；重复添加同一文件时应给出提示，避免误提交。
- 页面应为队列中的每个文件展示文件名、文件大小、识别出的源格式和上传状态。
- 页面仅展示当前已支持的目标格式，避免用户选择不支持的转换路径。
- 上传过程中展示每个文件的上传进度；上传失败时展示可理解的失败原因，且不影响队列中其他文件。
- 首期仅支持拖入文件，不包含拖入文件夹及其递归扫描。

### 3.3 转换配置与任务创建

- 用户可为单个文件选择目标格式，也可对多个兼容文件批量应用同一目标格式。
- 同一 Task 内允许同时存在不同源格式、不同目标格式的转换项。
- 用户提交队列后，系统在当前 Task 中为每个文件创建独立转换项并异步执行。
- 前端应校验每个文件是否已选择有效目标格式；不支持的文件或转换组合不可提交，但不应阻塞队列中其他有效文件。
- 对 Markdown 转 DOCX，预留“使用 DOCX 样式模板”的配置入口；首期是否开放模板上传待确认。
- 对 Markdown 转 XLSX，应向用户说明其语义是“将 Markdown 表格导出为工作表”。

### 3.4 任务状态展示

- 创建 Task 后，页面展示 Task 总体状态和每个转换项的独立状态。
- 单文件首期状态包括：`上传中`、`排队中`、`转换中`、`待预览`、`转换失败`、`结果已过期`。
- Task 状态应展示转换项总数、已成功数、失败数、处理中数量和待预览数量。
- 转换中页面显示刷新中的状态，不能错误地提示转换完成。
- 转换失败时展示可供用户理解的错误信息；不直接暴露内部命令、路径或敏感日志。

### 3.5 结果暂存、预览与导出

- 转换成功后的结果先暂存在 Web 服务中，系统不得自动下载或写入用户本地磁盘。
- 用户能够查看结果文件名、格式、文件大小和生成时间。
- Markdown 结果支持渲染预览和源文本预览。
- HTML 结果支持受限的页面预览。
- DOCX 结果支持只读内容预览；预览用于确认正文结构和主要样式，不承诺与本地 Word 的像素级一致。
- XLSX 结果支持只读表格预览，可查看工作表名称、表头和单元格内容。
- 结果预览成功后，用户可选中一个或多个结果并点击“导出到本地”。
- Web 服务通过浏览器下载机制导出文件；实际保存目录和浏览器下载确认由用户浏览器控制。
- 对未导出的暂存结果，用户仍可在结果未过期前预览和下载。
- 用户可在预览后删除当前 Task 中不需要的已完成转换项；删除后该结果不再出现在 Task 中，也不能被导出。
- 删除转换项必须经过二次确认；Task 中其他转换项及其结果不受影响。
- 首期删除的对象为生成结果及其预览临时数据；是否同步删除原始上传文件待确认。
- 用户可在 Task 中选择保留的一个或多个结果导出，也可导出该 Task 中全部未删除且未过期的结果。

### 3.6 任务记录

- 当前登录用户可查看自己已创建的 Task 列表及每个 Task 的转换项列表。
- 用户可进入某个 Task，继续添加文件、查看转换状态、预览结果、删除结果和导出结果。
- 每条文件任务至少展示源文件名、源格式、目标格式、创建时间和当前状态。
- 用户可从 Task 中重新预览或导出尚未过期且未删除的结果。

团队协作、多角色权限和多人共享不属于当前 MVP。

## 4. 后端功能

### 4.1 转换任务管理

- 支持已登录用户创建一个 Task，并向该 Task 接收多个上传文件及其各自的目标格式。
- 每个 Task 必须关联创建它的 `user_id`；用户只能访问、预览、删除和导出自己 Task 内的文件。
- 在一个 Task 中创建多个独立转换项；转换项之间允许使用不同转换路径。
- 每个任务独立校验文件扩展名、源格式和目标格式是否在支持矩阵中。
- 将文件和任务分离管理：任务记录保存状态与元数据，原文件和结果文件保存为独立文件对象。
- 转换采用异步执行，创建任务的请求不等待耗时转换完成。
- 后端可查询 Task 汇总、单文件转换项状态、失败原因摘要和结果文件信息。

### 4.2 转换执行路由

- 对 `DOCX/PPTX/XLSX/HTML/PDF -> Markdown` 路径，调用配置的 Markdown 提取能力。
- 对 `Markdown -> DOCX/HTML` 路径，调用配置的文档生成能力。
- 对 `Markdown -> XLSX` 路径，调用专用的表格导出能力。
- 引擎调用失败、超时或返回异常结果时，任务必须标记为失败并记录原因。
- 引擎实现可替换；上层任务接口不应依赖某个具体命令行参数或编程语言运行时。

### 4.3 Markdown 转 XLSX 规则

- 一个 Markdown 表格转换为一个 Excel 工作表中的表格区域。
- 多个 Markdown 表格转换为多个工作表。
- 表格前最近的 Markdown 标题用于生成工作表名称；无标题时使用顺序名称。
- 工作表名称应符合 Excel 的命名限制；发生重名时自动生成不重复名称。
- 第一行作为表头；后续行作为数据行。
- 对齐标记仅用于 Markdown 解析，不写入 Excel 数据。
- 普通段落、列表、代码块和图片不保证转换为 Excel 的等价排版；可在“说明”工作表中以文本保留，具体是否实现待确认。

### 4.4 文件与结果生命周期

- 上传的源文件与生成的结果文件均应关联到任务。
- 转换成功后，结果文件和其预览所需的临时数据应先保存于服务端，任务转为“待预览”。
- 用户确认后可发起结果下载；下载操作不代表服务端能够确认文件已保存到用户的本地路径。
- 成功任务在结果未过期前必须支持预览和下载对应结果文件。
- 用户删除已完成转换项后，服务端应立即使该结果及其预览数据不可访问，并将其从该 Task 的可导出集合中移除。
- 文件失效或被清理后，任务状态应反映为“结果已过期”。
- 源文件、结果文件和预览文件暂存于后端机器指定的持久化目录，并按用户目录与 Task 目录分层保存；文件保留时长和清理策略待确认。

### 4.5 错误处理

- 不支持的格式或转换组合应在任务创建阶段直接拒绝。
- 文件损坏、密码保护、内容无法解析、引擎异常和执行超时应返回可区分的失败类型。
- 服务端保留排障所需的日志；用户侧仅看到脱敏后的错误说明。

### 4.6 用户、验证码与头像管理

- 保存用户的用户名、邮箱、邮箱验证状态、头像文件引用和创建/更新时间等基础资料。
- 用户名、邮箱必须唯一；注册前应校验格式和重复情况。
- 用户请求邮箱验证码时，后端通过网易邮箱 SMTP 服务发送；验证码必须设置有效期、单次使用和发送频率限制。
- 数据库只保存验证码摘要、用途、过期时间和使用状态，不能明文保存验证码。
- 头像文件保存到后端机器 `users/{user_id}/profile/avatar/` 目录，数据库保存其资产标识或相对路径。
- 头像下载必须经由用户资料 API 提供，不能向前端泄露服务器真实文件路径。

## 5. 容器化交付功能

- 提供前端镜像：托管前端构建产物。
- 提供 API 服务镜像：处理用户资料、网易 SMTP 验证码、Task 创建、Task 内批量上传、转换项创建、状态查询、预览授权、结果删除和按 Task 导出。
- 提供转换 Worker 镜像：内置文档转换和 Markdown 转 XLSX 所需运行环境。
- 提供本地联调用的容器编排文件，使前端、API、Worker 和数据存储能够一键启动。
- Worker 与 API 进程以非 root 用户运行，并限制其对宿主文件系统的访问范围。

数据库类型、镜像仓库和生产部署平台待确认。

## 6. 非功能要求

### 6.1 安全性

- 不允许用户通过文件名、Markdown 内容或转换参数注入系统命令。
- 转换进程必须有执行超时、内存和 CPU 资源限制。
- 转换容器只能访问任务临时目录，不访问宿主敏感目录。
- 下载结果时应校验任务与结果文件的关联关系，避免按任意路径读取文件。
- HTML 预览应采用隔离机制，避免转换结果中的脚本访问主站页面或用户数据。
- 网易 SMTP 的主机、账号和授权码必须以部署环境的机密配置提供，禁止写入代码、镜像或日志。
- 头像上传必须校验允许的图片类型和大小，并使用服务端生成的文件名。

### 6.2 可用性与可观测性

- 任务状态变化必须可查询。
- 关键操作应记录任务标识、转换路径、耗时、执行结果和失败分类。
- 创建 Task、添加转换项、删除转换项和导出结果均应记录审计日志。
- 单个任务失败不应导致 API 服务或其他任务中断。

### 6.3 兼容性

- 前端应支持当前主流桌面浏览器。
- API 应使用稳定、版本化的 HTTP 接口；用户、Task 和文件访问均需校验当前登录用户身份。
- 同一转换任务的输入、转换参数和引擎版本应可追溯，以便排查结果差异。

文件大小上限、并发量、单任务时限和性能指标待确认。

## 7. 不在 MVP 范围内

- PDF 转 DOCX。
- OCR 扫描件识别及版面还原。
- 复杂 Word、Excel、PPT 的像素级排版保真。
- 团队协作、多角色权限和多人共享。
- 在线编辑文档内容。
- DOCX、XLSX 的像素级原生应用预览效果。
- 任意格式之间的自由组合转换。

## 8. 验收标准

- 用户可创建一个 Task，并通过文件选择或拖拽将多个文件加入该 Task 的待转换队列。
- 用户可以使用用户名、邮箱和网易 SMTP 发送的首次邮箱验证码完成注册，且未验证邮箱不能创建 Task。
- 用户可查看自己的基础资料并上传或替换头像，服务器真实头像路径不会暴露给浏览器。
- 同一 Task 中可提交不同源格式、不同目标格式的有效转换项，并分别查看上传进度与转换状态。
- 用户能够完成已支持格式的 Task 创建、单文件转换项状态查看、服务端暂存结果预览、删除不满意结果和确认后按 Task 下载导出。
- 不支持的格式和转换组合会被清晰拒绝。
- Markdown 转 DOCX 能正确保留常见标题、段落、列表、表格、链接和图片引用结构。
- Markdown 转 XLSX 能将合法 Markdown 表格转换为可打开的 `.xlsx` 文件，多张表格能生成多个工作表。
- PDF 转 DOCX 在界面和 API 中均不可选择、不可提交。
- 转换失败、超时或引擎异常时，任务会进入失败状态，且服务仍能继续处理其他任务。
- 使用容器编排启动后，能够在本地完成“创建 Task → 批量拖拽上传 → 分别转换 → 预览或删除结果 → 按 Task 浏览器下载导出”的端到端流程。

## 9. 待确认事项

以下内容尚未确认，确认后应更新本文档并据此进入详细设计：

1. 单个文件大小上限、单个 Task 的文件数量上限、每日任务量及并发转换数。
2. 注册后的登录方式：用户名/邮箱 + 密码，还是每次使用邮箱验证码；如使用密码，还需确定密码规则、找回密码与修改密码范围。
3. 原文件和结果文件的保留时长及人工删除能力。
4. 是否支持上传 DOCX 模板来控制 Markdown 转 DOCX 的样式。
5. Markdown 中非表格内容是否需要写入 XLSX 的“说明”工作表。
6. PDF 转 Markdown 是否只支持含文本 PDF，还是未来增加 OCR。
7. 首期部署目标：本地私有化、内网服务器或公网 SaaS。
8. 批量导出时采用逐个浏览器下载，还是提供一个包含所有已选结果的 ZIP 文件。
9. 删除转换项时，是否同时删除其原始上传文件；若不删除，原始文件的保留时长如何设置。
